# Contributing

Thanks for looking. **Binacle.Net is not taking code contributions at the moment.** That is a deliberate
position, not an oversight, and everything below says what to do instead.

## 🐛 What is welcome, and it is most of it

**Issues, for reports.** Bugs and anything that does not behave the way the documentation says it should.
There is no bar. A one-line "this is wrong and here is what I ran" is genuinely useful.

**Corrections to the documentation.** Open an issue saying what is wrong and where, and I will fix it. You do
not need to write the fix.

**Questions and ideas go to [Discussions](https://github.com/binacle-labs/Binacle.Net/discussions)**, not to
the issue tracker. Anything not built yet belongs there too.

**What you are building.** If you are using this for something, say so in a discussion. Knowing what people
actually do with it changes what gets built next, and almost nobody tells me.

## 🚫 Why pull requests are closed for now

This has been a one-author project since 2023, and taking someone else's code needs contribution terms that
do not exist yet. Writing those terms properly is worth doing before the first pull request rather than after,
so the door stays shut until they are.

**A pull request opened today will be closed with a link to this file.** That is not a judgement on the
change. It is that I cannot merge it cleanly, and merging it anyway would be worse for both of us.

**This will change.** When the terms are settled, this file is the first place that will say so.

## 🍴 Forking is fine

The licence says what you may do and this file does not narrow it. Fork it, change it, run it, build on it.
[NOTICE](NOTICE) is the map of which licence covers which part of the repository, and the parts most likely
to be useful on their own - the ViPaq and compact notation libraries, the samples, the build tooling - are
deliberately permissive.

If you fix something in your fork, open an issue describing the fix. I would rather read the description and
write it myself than leave it broken.

## 🔒 Security

**Not in an issue.** Use GitHub's private advisory route, which [SECURITY.md](SECURITY.md) explains along
with which versions are supported and how to verify a published image.

## 🛠️ Building it yourself

[DEVELOPMENT.md](DEVELOPMENT.md) covers the toolchain, the install steps and the task runner. You do not need
any of it to file an issue.
