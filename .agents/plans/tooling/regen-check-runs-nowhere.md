# The drift check nobody runs, and cannot pass

**Was `unwatched-gaps.md`.** Three of the four gaps in that file are closed and this is the fourth.

**What `regen` covers is settled**: data generated *into* the repository, and nothing else. The docs site's
OpenAPI copies are not that - they are hand-carried, and `just openapi check-site-copies` compares them now.

## No workflow calls it

`grep -rn regen .github/workflows/` returns nothing. The recipe that exists to catch generated data drifting
only ever runs when someone runs it by hand, which means the four generators' output can go stale on `main`
and nothing says so.

## And when it does run, it fails

`vipaq/test-vectors/interop/cs/deflate.json` and `gzip.json` come back different. Three of the fourteen
vectors in each file change - checked 2026-08-31 on .NET SDK 10.0.111.

**It is not a data problem.** The three are the ones large enough for deflate to compress rather than store,
the new bytes are shorter every time, and the ViPaq suites pass on both sets: 421 C# and 380 TypeScript
against the committed vectors, and the same numbers against the regenerated ones.

**The cause is that .NET's deflate output is not stable across runtime patch versions, and `global.json`
pins no SDK.** So the committed bytes record which SDK happened to be installed when someone last ran the
generator. Regenerating fixes it until the next SDK update, then it comes back.

## The three ways out, and they are not equal

| | What it costs | What it leaves |
|---|---|---|
| **Commit the regenerated bytes** | nothing today | it recurs on every SDK patch bump, and each time it looks like a real diff |
| **Pin the SDK in `global.json`** | constrains every build on every machine and in CI to one SDK band | the check becomes honest, and the pin has to be maintained |
| **Stop byte-comparing those two files** - decode and compare what the vectors mean | one change to the check | the only one that stops the question coming back. It is also what the interop suites already do |

**The third is the one that ends it.** The first two both leave a check that is right only until the next
SDK moves.

**Whichever is chosen, a workflow then has to call `just regen check`** - that half is not optional and is
the reason this file exists. It belongs beside the other repo-wide checks in the pull request gate.

## Done when

**What it takes: one answer, then one change and one workflow step.**

- [ ] `just regen check` passes on a clean tree.
      Run it. Either the two ViPaq vector files stop being byte-compared, or `global.json` pins the SDK, or
      the regenerated bytes are committed and the recurrence is written down as accepted.
- [ ] Something other than a person runs it.
      `grep -rn 'regen check' .github/workflows/` matches.

Then delete this file.
